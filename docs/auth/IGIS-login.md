# IGIS 계정 연결 — 구현 및 운영 적용 기록

기존 지도·자산 상세·비교·매매이력은 로그인 없이 이용한다. 관심건물 저장과 관리자 기능에만 인증을 적용한다. 공개 조회는 만료되거나 중지된 로그인 상태에서도 동일하다.

상태: 2026-09-22 운영 적용 승인 후 공개 조회·IGIS identity migration, 양쪽 Edge 함수, 원본 직원 테이블 보호, 비밀번호 복귀 주소를 적용했다. 원본 IGIS 가입 화면 변경은 340078f로 운영 배포 성공. 원본 보호 RPC=true, 양쪽 함수 CORS=200, 미인증 연결 요청=401 확인. 자산 364개·매매이력 355건 공개 조회 유지. Workplace 프런트엔드 ff8fca1 운영 배포 성공(Deploy website #3). 18:33 기존 전기영 계정의 인증 연결·권한 동기화 POST 200을 서버 로그에서 확인했다. 관리자 연결 DB도 생성됐다. 비밀번호 변경·재설정 메일 발송은 하지 않았다.

## 사용자 경험

- 기존 직원 이메일 확인 → 기존 비밀번호 로그인.
- 최초 이용자는 접속 코드 → 비밀번호·확인 입력. 가입과 직원 계정 연결은 기존 IGIS 프로젝트의 `igis-enroll` 서버에서 처리.
- 기존 비밀번호를 확인한 뒤 변경 / 이메일로 비밀번호 찾기 / 링크에서 새 비밀번호 설정.
- IGIS Auth의 비밀번호를 그대로 사용하며 Workplace에는 비밀번호를 저장하지 않는다.
- 비밀번호 변경은 같은 IGIS 계정을 쓰는 다른 서비스에도 적용된다.
- 메일은 기존 IGIS Supabase의 메일 발송 설정을 사용한다. 실제 발송 성공은 아직 검증하지 않았으며, 기본 메일 발송 한도가 적용되는 프로젝트라면 비밀번호 찾기도 그 제한을 받는다.

## 연결 방식

IGIS `qgrszltduzblpvpqvkqr` → Workplace `hakttwxctqfxcqbwdavw`.

Workplace의 `igis-auth` 서버 함수가 IGIS Auth의 `getUser(token)`으로 인증을 검증한다. 직원 테이블의 활성 상태·이메일·연결된 Auth ID를 대조한 후에만 Workplace 세션을 발급한다. 브라우저가 보낸 역할이나 이메일은 인증 근거로 사용하지 않는다. 서버 내부에서 1회성 로그인 토큰을 소비하며, 이 과정에서 로그인 메일을 발송하지 않는다. OAuth 서버(Beta)를 켜거나 기존 IGIS Site URL을 바꿀 필요가 없다.

`private.workplace_members`에는 양쪽 계정 연결, 표시용 이름·이메일, 서비스 권한만 저장한다. 회사 전체 직원 명부를 복제하지 않는다. 기존 IGIS `role_code`는 Workplace 권한으로 자동 승격하지 않는다.

| 기능 | 비로그인 | viewer | editor | admin |
|---|---|---|---|---|
| 지도·자산 상세·비교·매매사례 조회 | 허용 | 허용 | 허용 | 허용 |
| 관심 자산 저장 | 로그인 안내 | 허용 | 허용 | 허용 |
| 사진 관리 | 차단 | 차단 | 허용 | 허용 |
| 사용자 권한 관리 RPC | 차단 | 차단 | 차단 | 허용 |

공개 조회는 권한 재정의나 로그인 만료 여부와 관계없이 이용할 수 있다. 권한 제한은 개인화·관리 기능에만 적용한다.

`permissions`의 기능별 true/false 설정으로 역할의 기본값을 재정의할 수 있다. 사용자 관리 화면은 이번 변경에 포함하지 않았으며, 관리자 RPC와 서버 검증을 준비했다. 초기 관리자는 기획추진센터의 **이시정·이관용·전기영** 세 명이다. 2026-09-22 기존 직원 DB에서 세 명 모두 `기획추진` 소속의 활성 계정임을 확인했다. `private.workplace_initial_roles`에 직원 고유 ID로 초기 admin 역할을 지정하고, 최초 로그인 시 `private.workplace_members`로 반영한다. 이름·이메일이나 기존 검수 허용 목록으로 관리자를 자동 지정하지 않는다. 그 외 직원의 초기 역할은 viewer다. 이후 역할·기능별 권한 변경은 Workplace DB에서 관리하며 재로그인으로 초기 권한을 덮어쓰지 않는다. 향후 관리 메뉴는 같은 admin 역할과 기능별 권한 검사로 확장한다. 초기 관리자 설정은 운영 DB에 반영했다.

활성 상태는 열린 화면에서 45초마다 및 창 복귀 시 확인한다. DB는 2분짜리 검증 유효기간을 검사하므로, 서버 확인이 끊기면 늦어도 2분 뒤 개인 저장·관리 기능 접근이 거부된다. 즉시 웹훅 동기화는 아니다. 로컬 enabled=false나 권한 변경은 다음 DB 요청부터 적용된다. 이미 다운로드한 자료/발급된 Storage 서명 URL은 회수되지 않는다.

## 운영 전 필수: 기존 직원 테이블 보호

2026-09-22 실제 Supabase Policies 화면에서 `Allow individual update`가 public / UPDATE / USING(true)인 것을 확인했다. 직원 활성 여부와 계정 연결을 그대로 신뢰하며 서비스를 열면 안 된다.

- `igis-source-guard.sql`: 기존 직원 명부의 계정·이메일·활성 상태·역할 변경을 브라우저에서 금지한다. 본인의 마지막 로그인 시각 갱신은 유지한다. 기존 SELECT/다른 업무 테이블은 건드리지 않는다.
- `scripts/auth/prepare-source-login.mjs`: 기존 IGIS AuthSetup의 최초 가입만 서버 검증으로 바꾼 `/tmp/igis-AuthSetup.jsx`를 준비한다. 소스 저장소는 수정하지 않는다. 이 파일은 기존 화면/비밀번호 로그인/변경/찾기/로그인 이력을 유지한다.
- 두 변경은 함께 반영해야 한다. 보호 SQL만 반영하면 기존 플랫폼의 첫 가입 시 계정 연결이 차단된다.
- 서버 함수는 `workplace_identity_guard_ready()`로 원본 DB 보호 여부를 확인하고, 미적용 상태에서는 로그인 연결 자체를 거절한다.
- 기존 접속 코드는 공개 프런트엔드에 포함되어 있었으므로, 운영 전 서버 전용 코드로 교체하는 것이 바람직하다. 새 코드 값은 저장소나 문서에 넣지 않는다.

## 배포 순서

1. 공개 조회 migration `202609220000_public_browsing.sql`은 인증 배포와 독립적으로 적용한다. 이후 Workplace migration `202609220001_igis_identity.sql` 적용.
2. Workplace Edge secrets에는 `IGIS_URL`, `IGIS_ANON_KEY`(공개 키)만 설정한다. 기존 IGIS 프로젝트에는 `IGIS_FIRST_ACCESS_CODE`를 서버 전용 secret으로 설정하고 `supabase/source-functions/igis-enroll/index.ts`를 `igis-enroll`로 배포한다. 두 함수는 각각 자기 프로젝트의 기본 `SUPABASE_*` Edge secrets를 사용한다. 원본 관리자 키를 Workplace로 복사하지 않는다. 접속 코드는 UI/저장소/로그에 넣지 않는다.
3. Workplace에 `igis-auth` 배포. 두 함수 모두 gateway `verify_jwt=false`로 배포하되 `igis-enroll`은 서버 접속 코드·등록 직원·요청 제한을 검증한다. 외부 IGIS 토큰을 직접 검증하므로 gateway `verify_jwt=false`; 함수 자체가 토큰·직원·Origin을 검증한다.
4. 준비된 IGIS AuthSetup 변경과 원본 보호 SQL을 함께 반영. 기존 등록 계정 로그인, 최초 가입, 로그인 시각 갱신 확인.
5. IGIS Auth의 기존 Site URL/Redirect 항목을 유지하고 다음 정확한 Redirect URL만 추가:
   - `https://this8369.github.io/workplace-seoul/?igis-recovery=1`
   - `http://127.0.0.1:5173/?igis-recovery=1`
6. 실제 직원 계정으로 Workplace 로그인·저장, 일반 직원의 사진 관리 차단, 관리자 기능, 로그아웃, 비밀번호 찾기/재설정 검증. 실제 직원 비밀번호는 자동 테스트로 변경하지 않는다.
7. Workplace 프런트엔드를 GitHub Pages에 배포.

기존 IGIS 저장소는 별도 작업 경로이며 그 저장소의 변경 기록/배포 지침도 적용한다. 2026-09-22 사용자가 운영 적용과 로그인 확인을 승인했다. 기존 가입 코드 값은 변경하지 않고 원본 프로젝트의 서버 secret으로 이전했다.

## 검증

- IGIS 서버 검증 실패·비활성 직원·다른 직원 auth_id·타인 Workplace 토큰·로컬 권한 중지·잘못된 Origin 거절.
- 서버 토큰을 브라우저 입력 이메일/역할로 위조하거나 자체적으로 권한 승격할 수 없음.
- viewer의 사진 등록·대표 사진 설정 차단, editor 허용, 개별 기능 차단, 만료 세션 관리 기능 차단 및 공개 조회 유지.
- 원본 DB는 보호 적용 후 직원 계정/역할/활성 상태 변경·직원 생성·삭제 거절. 본인 로그인 시각 갱신 유지.
- 브라우저에서 로그인 창, 실제 직원 이메일 확인 → 비밀번호 화면, 비밀번호 찾기 전환 확인. 실제 로그인/메일 발송/비밀번호 변경은 운영 연결 후 확인할 항목.

## 2026-09-22 장애 수정 결과

원인은 igis-auth 미배포로 인한 OPTIONS 404/CORS 실패였다. 비밀번호 검증 실패가 아니었다. 원본 최초 가입 서버 함수와 직원 보호를 함께 배포한 뒤 두 함수 OPTIONS 200, 인증 없는 exchange 401, 정상 직원 exchange/sync 200을 확인했다. 로컬 테스트 59개와 GitHub 운영 빌드·배포가 통과했다. 기존 비로그인 자산·매매사례 조회도 유지했다.
