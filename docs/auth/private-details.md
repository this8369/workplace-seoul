# 공개 리스트와 회원 상세정보 경계

2026-10-12 사용자 결정: 기존 서비스의 리스트만 공개하고 모든 상세페이지는 등록 사용자 전용으로 전환한다.

## 공개

`catalog_*` 뷰에 명시한 기존 리스트/지도 필드만 공개한다. 자산 이름·주소·좌표·면적·준공연도·기준층·최신 NOC·개발 요약, 매매사례 목록, 지도 경계 좌표, 승인된 대표 썸네일이다. 공개 목록의 `private.catalog_publications`에 없는 신규 레코드는 기본 비공개다. 뷰는 원본의 새 컬럼을 자동으로 포함하지 않는다.

뷰는 의도적으로 소유자 권한을 쓰며 `security_barrier`와 명시적 컬럼/레코드 허용 목록으로 범위를 제한한다. 브라우저에는 SELECT만 허용한다. 원본을 읽는 `security_invoker` 뷰로 바꾸면 공개 리스트는 동작하지 않는다.

## 회원 전용

원본 자산, 기업, 거래 세부사항, 임대 이력, 입주기업, 토지 특성·공시지가, 건축물대장, 상세 사진은 등록 회원만 읽는다. Auth 계정만으로는 부족하며 IGIS 명부와 연결된 Workplace 회원의 enabled, verified_until, details.read를 DB에서 확인한다. transactions.read 등 서비스별 권한도 적용한다. 원본 테이블의 anon 권한을 제거하고 authenticated에는 restrictive RLS를 적용한다. TRUNCATE 등 RLS를 우회하는 불필요한 권한도 제거한다.

로그인 후 클릭한 자산의 데이터만 요청한다. 상세 데이터는 공개 카탈로그나 sessionStorage에 섞지 않는다. 권한 만료·로그아웃 시 컴포넌트를 내리고 메모리와 사진 blob URL을 해제한다. 상세 사진은 인증 헤더로 다운로드하며 공개 서명 URL을 새로 발급하지 않는다. 이미 과거에 발급된 서명 URL은 기존 만료 시각까지 유효하고, 이미 내려받은 정보는 회수할 수 없다.

## 다음 마스터 DB

주요 엔터티는 자산과 기업이다. 자산 유형은 오피스·호텔·물류·DC로 확장한다. 제공될 펀드·대주·수익자·투자자산·AUM은 각 원본의 식별자를 보존하고 별도 관계 및 기준일/이력으로 연결한다. 관계의 다중성, 지분·금액 기준, 중복 판정은 실제 자료를 받은 후 결정한다. 기존 건물/기업 ID는 유지하고 새 마스터의 연결키로 쓴다.

신규 내부 원장 및 원본 적재는 API 비노출 `private` 스키마에 둔다. 브라우저에 schema/table 접근 권한을 주지 않는다. 새 기능은 좁은 필드의 인증 RPC 또는 서버 API를 추가하며 매번 회원 및 기능별 권한을 확인한다. SECURITY DEFINER RPC는 빈 search_path와 명시적 EXECUTE 권한을 사용하고 anon·미등록·비활성·만료·권한 거부 테스트를 포함한다. 이 문서만으로 아직 없는 테이블의 보안 검증이 완료된 것은 아니다.

개인정보·펀드 원장·대출·수익자·AUM 원본은 공개 Git 저장소, 정적 public 폴더, 프런트엔드 번들, 공개 Google Sheet에 넣지 않는다. 공개 리스트로 승격할 레코드/필드는 별도 검토한다. 기존 ID의 공개 필드에 내부 정보를 덮어쓰지 않는다. 마이그레이션은 postgres 소유자로 적용하며 다른 DDL 역할을 추가하면 해당 역할의 기본 권한도 별도 확인한다.

공개 리스트는 누구나 조회할 수 있다. 로그인 없이 상세 API를 조회하는 것은 거부되지만, 정당하게 권한을 받은 사람이 내려받은 정보를 복사하는 것까지 RLS가 막는 것은 아니다.

운영 전환은 `202610120001`(공개 뷰 준비) → 신규 프런트엔드 배포 → `202610120002`(기존 원본 접근 차단) 순서로 한다. 대표 사진을 관리자가 승인하면 기존 공개 자산의 썸네일만 공개 목록에 추가한다. 상세 사진·관리 메모는 포함하지 않는다. 검색엔진 noindex는 보조 설정이며 DB 권한을 대체하지 않는다.
